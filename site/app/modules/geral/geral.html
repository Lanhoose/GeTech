Introdução ao Sistema

Sistema de gestão industrial desenvolvido como projeto educacional, simulando um ERP real com múltiplos módulos. O repositório é dividido em três zonas: Site C (portal do cliente e porta de entrada do projeto), public (site institucional do produto) e app (painel ERP interno, restrito ao perfil gestor).

A autenticação e a persistência deixaram de ser simuladas em localStorage: hoje o projeto usa Firebase Authentication e Firebase Realtime Database como fonte única da verdade, com as regras de acesso versionadas em database.rules.json.

Ponto de entrada
index.html da raiz → Site C
⚠️ Os scripts montam os caminhos a partir de window.location.origin + "/GeTech". O projeto precisa ser servido com a pasta GeTech na raiz da URL (ex.: http://127.0.0.1:5500/GeTech/index.html), senão os redirecionamentos de login quebram.
⚠️ Abrir os arquivos direto pelo navegador (file://) não funciona: o fetch() dos componentes e os <script type="module"> do Firebase exigem protocolo HTTP.

Sistema de Componentes

Header e footer são carregados via fetch() nas páginas do site institucional (public/), evitando duplicação de código. O app/ e o Site C/ montam seus próprios cabeçalhos.

// component.js function carregarComponente(id, arquivo) { fetch(arquivo) .then(res => res.text()) .then(data => { document.getElementById(id).innerHTML = data; }); } document.addEventListener("DOMContentLoaded", () => { carregarComponente("header", "../components/header.html"); carregarComponente("footer", "../components/footer.html"); });

Autenticação (Firebase)

Toda a configuração fica em um único arquivo — Site C/assets/js/firebase-config.js — que exporta auth e db. Os módulos do app/ importam esse mesmo arquivo por caminho relativo.

EtapaArquivoO que acontece
1. CadastroSite C/assets/js/cadastro.jsCria a conta no Firebase Auth e grava {nome, email, tipo} em usuarios/{uid}
2. LoginSite C/assets/js/login.jssignInWithEmailAndPassword() — a sessão passa a ser gerenciada pelo Firebase
3. Proteção do painelapp/assets/js/app.jsonAuthStateChanged() lê o perfil e só libera se tipo === "gestor"
4. Proteção por móduloestoque.js, rh.js, manutencao.js, orderns.js, logs.jsCada módulo repete a verificação — abrir a URL direto não contorna o bloqueio
5. Logoutapp.jsRegistra a auditoria, executa signOut() e volta ao portal
// padrão de proteção usado em todos os módulos onAuthStateChanged(auth, async (user) => { if (!user) { location.href = '../../Site C/pages/login.html'; return; } const snap = await get(ref(db, `usuarios/${user.uid}`)); if (!snap.exists() || snap.val().tipo !== 'gestor') { alert('Acesso restrito.'); location.href = '../../Site C/pages/login.html'; return; } carregar(); // libera o módulo });
⚠️ As chaves do Firebase ficam expostas no front-end — isso é esperado. A segurança real depende das regras de database.rules.json, que precisam estar publicadas no console do Firebase.

Trilha de Auditoria

Ações relevantes (login, logout, cadastros, exclusões) chamam registrarAuditoria(), exportado por assets/js/auditoria.js, que grava o evento no nó auditoria com usuário, data/hora, ação, detalhe e criticidade. O módulo Logs lê esse nó em tempo real e mantém no máximo 500 registros.

import { registrarAuditoria } from './auditoria.js'; await registrarAuditoria('Estoque: novo item', `Item ${nome} cadastrado.`, 'info');

Regras de Segurança

O arquivo database.rules.json (raiz do repositório) começa negando tudo e libera nó a nó. O padrão é sempre o mesmo:

{ "rules": { ".read": false, ".write": false, "estoque": { ".read": "auth != null && root.child('usuarios').child(auth.uid).child('tipo').val() === 'gestor'", ".write": "auth != null && root.child('usuarios').child(auth.uid).child('tipo').val() === 'gestor'" } } }
ExceçãoRegra aplicada
usuarios/{uid}O próprio usuário lê e cria seu registro; só gestor altera o campo tipo
postsBlogLeitura para qualquer usuário autenticado; escrita só para gestor
chamadosChatbotPermite abrir um chamado novo e válido; leitura e edição só para gestor
auditoriaRegistros não podem ser sobrescritos por quem não é gestor; exige id, dataHora, usuario e acao
💡 Alterou as regras? Publique no console (Realtime Database → Regras). O arquivo do repositório é apenas a versão de referência — ele não é aplicado sozinho.

Como Rodar o Projeto

# 1. Abra no VS Code a pasta que CONTÉM o diretório GeTech # 2. Inicie o Live Server # 3. Acesse: http://127.0.0.1:5500/GeTech/index.html
Sem a pasta GeTech na raiz da URL, o BASE_URL montado em app.js e logs.js aponta para caminhos inexistentes e o login entra em loop de redirecionamento.

Como Criar uma Nova Página Pública

1. Copie o template

cp public/pages/_template.html public/pages/minha-pagina.html

2. Estrutura mínima obrigatória

<div id="header"></div> <!-- carregado pelo component.js --> <main class="container"> <!-- conteúdo da página --> </main> <div id="footer"></div> <!-- carregado pelo component.js --> <script src="../assets/js/component.js"></script>

3. Adicione no header

Edite public/components/header.html e adicione o link na tag <nav>.

Como Criar um Novo Módulo ERP

1. Crie a pasta e o arquivo (a pasta e o HTML precisam ter o mesmo nome)

app/modules/nome-modulo/nome-modulo.html

2. Importe os estilos e os scripts padrão

<link rel="stylesheet" href="../../assets/css/global.css"> <link rel="stylesheet" href="../../assets/css/nome-modulo.css"> <script src="../../assets/js/acessibilidade.js"></script> <script type="module" src="../../assets/js/logs.js"></script>

3. Proteja o módulo e registre auditoria

import { auth, db } from "../../../Site C/assets/js/firebase-config.js"; import { registrarAuditoria } from "./auditoria.js"; // + onAuthStateChanged conferindo tipo === 'gestor' (ver aba Arquitetura)

4. Adicione o card no dashboard (app.html)

<div class="card" onclick="abrirModulo('nome-modulo')"> <h3>Nome do Módulo</h3> <p>Descrição breve.</p> </div> // app.js monta o caminho automaticamente: // modules/nome-modulo/nome-modulo.html

5. Libere o nó no database.rules.json

Sem uma regra explícita, o nó novo herda o ".read": false / ".write": false da raiz e o módulo falha silenciosamente na leitura.

Como Expandir o Site C

O Site C é independente — não utiliza o component.js do site institucional. Cada nova página é criada em Site C/pages/, com CSS e JS próprios em Site C/assets/.

Nota: como não há sistema de componentes, cabeçalho e rodapé precisam ser replicados manualmente em cada página — ou extraídos para um componente próprio do Site C.
